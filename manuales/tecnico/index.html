Resumen

Qué es, quién lo usa y de qué depende.

Aplicación web interna que reemplaza el registro de vacaciones en hojas de cálculo: solicitudes de vacaciones y permisos con aprobación de jefe y Talento Humano, saldos por período (Código del Trabajo, Art. 69), documentos firmados con escaneo, control de garita con código QR, personal temporal, informes y exportaciones.

PiezaTecnología
InterfazHTML + módulos JavaScript (sin framework) + Tailwind CSS 3.4 compilado. Archivos estáticos.
APIPython 3.11, FastAPI 0.115, Uvicorn 0.34, Pydantic 2.10, aiomysql / PyMySQL.
Base de datosMySQL 8.0, base rrhh, utf8mb4_0900_ai_ci. Reglas críticas también en disparadores y funciones.
Documentosopenpyxl (Excel), reportlab (PDF), qrcode + Pillow (QR).
CorreoSMTP con STARTTLS (aiosmtplib). Envía los códigos de acceso y los avisos.
PublicaciónApache (HTTPS, puerto propio 8444) como proxy inverso; servicio y temporizadores de systemd.

El repositorio brantos102/RRHH_ITSANET es la única fuente del código. Todo cambio se hace ahí y el servidor lo trae con git pull (o con bash despliegue/actualizar.sh).

Lo que no se toca

El servidor aloja otros sistemas en producción. No se modifican IV ITSANET (base iv_itsanet, carpeta ~/bryan/IV_ITSANET), los sitios itsanet-app-8443.conf e itsanet-data-sync*.conf, ni los puertos 3000, 3002, 8000, 8080 y 8443. Este sistema usa solo 8010 (interno) y 8444 (web). Apache solo se recarga, y solo si apache2ctl configtest da «Syntax OK».

Primera instalación

Ya hecha en el servidor. Queda como referencia para una reinstalación.

cd ~/bryan/RRHH_ITSANET
git pull
# 1. Base y usuario de la aplicación (guarda la clave en servidor/.env)
bash despliegue/crear_base.sh
# 2. Estructura: primero revisar, después aplicar
sudo env MYSQL_URL="mysql://root@localhost/rrhh?unix_socket=/var/run/mysqld/mysqld.sock" .venv/bin/python mysql/migrar.py
sudo env MYSQL_URL="mysql://root@localhost/rrhh?unix_socket=/var/run/mysqld/mysqld.sock" .venv/bin/python mysql/migrar.py --aplicar
# 3. Correo y prueba
bash despliegue/configurar_correo.sh
.venv/bin/python despliegue/probar_correo.py correo.de.prueba@itsanet.com
# 4. Servicio, tareas, web y sitio de Apache (muestra todo y pregunta antes)
bash despliegue/instalar.sh
Certificado. La cámara de garita y el escaneo de cédulas exigen HTTPS. El instalador reutiliza el certificado de otro sitio del mismo Apache (solo lee la ruta). Para usar otro: CERT=/ruta/cert.pem LLAVE=/ruta/llave.key bash despliegue/instalar.sh.

Usuarios de la base

  • rrhh_app: el de la aplicación. Solo SELECT, INSERT, UPDATE, DELETE, EXECUTE sobre rrhh.*.
  • Usuario de solo lectura para consultas y DBeaver: bash despliegue/usuario_lectura.sh; acceso desde Windows por túnel SSH según despliegue/DBEAVER.md.
  • Las migraciones se aplican como root por el socket local (crean disparadores y funciones).
No se corrigen datos a mano en la base. Cada cambio en el aplicativo deja bitácora y mantiene los saldos coherentes. Para correcciones masivas existe Administración › Actualización masiva; para depurar, las consultas guiadas de mysql/depuracion/ (empezar por 00_LEER_PRIMERO.sql).

Respaldos y restauración

actualizar.sh respalda antes de cada actualización. Además, conviene uno diario fuera del servidor.

mkdir -p ~/bryan/rrhh_datos/respaldos
sudo mysqldump --single-transaction --routines --triggers rrhh > ~/bryan/rrhh_datos/respaldos/rrhh_$(date +%F_%H%M).sql
tar -czf ~/bryan/rrhh_datos/respaldos/adjuntos_$(date +%F_%H%M).tar.gz -C ~/bryan/rrhh_datos adjuntos
ls -lh ~/bryan/rrhh_datos/respaldos/

La base guarda la huella SHA-256 de cada escaneo firmado; sin el respaldo de adjuntos/, la auditoría tendría la huella pero no el documento. Los respaldos se copian a almacenamiento de la empresa, nunca a nubes o correos personales (LOPDP).

Restaurar (reemplaza todo lo actual; solo con autorización)

sudo systemctl stop rrhh-itsanet-api
sudo mysql rrhh < ~/bryan/rrhh_datos/respaldos/ARCHIVO.sql
sudo systemctl start rrhh-itsanet-api

systemctl is-active rrhh-itsanet-api                                  # debe decir: active
curl -k https://127.0.0.1:8444/api/salud                              # "estado":"ok","base_datos":"conectada"
sudo journalctl -u rrhh-itsanet-api --since "10 min ago" --no-pager | tail -40
sudo journalctl -u rrhh-itsanet-api -f                                # en vivo (Ctrl + C para salir)
sudo tail -40 /var/log/apache2/rrhh-itsanet-error.log

Cada línea del registro del backend lleva un identificador de petición y la cédula de quien la hizo, para seguir un caso de punta a punta. La bitácora funcional (quién hizo qué) está en la base y se consulta en Administración › Bitácora; no se puede editar ni borrar desde la aplicación.

Completar la planilla con quienes faltan

Procedimiento recomendado cuando la carga inicial no trajo a todo el personal activo.

  1. Respaldo (ver Respaldos).
  2. Nómina vigente: Talento Humano prepara en Excel la lista del personal activo hoy, con cédula, apellidos y nombres, fecha de ingreso y, de preferencia, el saldo de vacaciones conciliado a la fecha y el correo personal.
  3. Plantilla: Administración › Actualización masiva › Registrar personas nuevas › «Descargar plantilla de personas nuevas». Se pega la nómina respetando las columnas.
  4. Revisión: al subirla, el sistema ensaya cada alta dentro de una transacción que se deshace y muestra: quién se registraría (con el saldo resultante), cuántos ya estaban, los errores por fila y quién está en el sistema pero no en el archivo. No escribe nada.
  5. Corrección: se corrigen los errores en el Excel y se vuelve a subir (cada subida genera su folio; la anterior queda «revisada, sin aplicar» y conviene descartarla).
  6. Aplicar con un motivo. Todo entra en una sola transacción: o entran todas las altas de la carga, o ninguna.
  7. Después: registrar el correo de quien no lo tenga (Usuarios), asignar jefaturas (Jefaturas), revisar «Depuración › No pueden entrar», y dar de baja con su causa a quien figure en el sistema y ya no trabaje.

Alternativa por terminal, para TI: mysql/cargar_personas.py con un CSV (despliegue/personas_plantilla.csv), que exige correo y rol y también crea o actualiza por cédula.

Seguridad y protección de datos (LOPDP)

  • Sin contraseñas almacenadas: acceso por código de un solo uso; se guarda solo su hash, con vigencia, intentos máximos y límite de envíos por hora.
  • Sesiones: JWT de 8 horas ligado a una sesión revocable. Talento Humano puede cerrar todas las sesiones de una persona (celular perdido); cada persona ve y cierra las suyas en «Mi ficha».
  • Mínimo privilegio: el usuario de la aplicación no puede alterar la estructura; el backend escucha solo en 127.0.0.1; Apache publica solo HTTPS en 8444.
  • Datos sensibles (discapacidad, tipo de sangre, certificados médicos): visibles solo para la persona y Talento Humano; los adjuntos en carpeta con permisos 700; el jefe ve lo necesario para autorizar.
  • Trazabilidad: bitácora inmutable, folios en exportaciones (EXP-AAAA-NNNN) y cargas masivas (CM-AAAA-NNNN) con motivo obligatorio y huella del archivo.
  • Retención: registros de acceso 24 meses y auditoría 84 meses, depurados por el temporizador mensual.
  • Sin servicios externos de IA: el asistente responde con reglas en el propio servidor.
Pendientes de TI. Rotar la clave SMTP (se compartió durante la configuración) y volver a ejecutar bash despliegue/configurar_correo.sh. Si el cortafuegos está activo, abrir solo el 8444. El repositorio es público: no debe contener claves, datos de empleados, Excel ni CSV (el .gitignore los excluye); conviene evaluar hacerlo privado.

Publicar el manual de usuario

El manual de usuario está en manuales/usuario/ y se publica en GitHub Pages con el flujo .github/workflows/manual-usuario.yml, que sube solo esa carpeta. Una sola vez, en GitHub: Settings › Pages › Build and deployment › Source: GitHub Actions. Desde entonces se publica solo cada vez que cambia la carpeta (o a mano desde la pestaña Actions › «Publicar manual de usuario» › Run workflow).

Las capturas usan datos inventados y tapan cédulas y teléfonos. Este manual técnico no se publica en Pages.

Retirar el sistema

sudo systemctl disable --now rrhh-itsanet-api rrhh-itsanet-tareas.timer rrhh-itsanet-retencion.timer
sudo a2dissite rrhh-itsanet && sudo systemctl reload apache2

Deja Apache y el resto del servidor como estaban. La base rrhh y ~/bryan/rrhh_datos no se borran: son datos personales sujetos a la LOPDP y a su plazo de conservación.
