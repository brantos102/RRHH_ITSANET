# El código de acceso sale sin esperar al puerto 587 (17/11/2026)

En la prueba del 17/11 el puerto **587 no conectó** una de dos veces y el
correo salió por el **2525**. Funcionaba, pero cada código de acceso esperaba
12 segundos al 587 antes de pasar al 2525, con la persona mirando la pantalla.

## Qué cambia

- El sistema **recuerda el puerto que funcionó** y los envíos siguientes
  empiezan por ese. Si ese también falla, vuelve al otro.
- `probar_correo.py` y `configurar_correo.sh` muestran solo el inicio del
  usuario del proveedor (es una credencial; no debe quedar en capturas).
- Se recomienda dejar **2525 como principal** y 587 como respaldo (paso 2).

## Comandos, uno por uno

En la terminal de VS Code conectada al servidor (`enicolalde@apps`):

**1. Traer el código:**

```bash
cd ~/bryan/RRHH_ITSANET
```
```bash
bash despliegue/actualizar.sh
```

**2. Dejar el 2525 como principal** (no pide la clave otra vez):

```bash
sed -i 's/^SMTP_PORT=587$/SMTP_PORT=2525/; s/^SMTP_PORT_ALTERNO=2525$/SMTP_PORT_ALTERNO=587/' servidor/.env
```
```bash
grep -E '^SMTP_PORT' servidor/.env
```

Debe decir `SMTP_PORT=2525` y `SMTP_PORT_ALTERNO=587`.

**3. Reiniciar y probar:**

```bash
sudo systemctl restart rrhh-itsanet-api
```
```bash
.venv/bin/python despliegue/probar_correo.py su.correo@itsanet.com
```

Debe decir «Enviado» sin ninguna línea de «falló en el puerto».

## Qué probar

1. Cerrar sesión y pedir el código: debe llegar en pocos segundos.
2. Si algún día el 2525 se cierra, el sistema pasa solo al 587; el registro
   lo dice: `sudo journalctl -u rrhh-itsanet-api -n 50 --no-pager | grep puerto`
